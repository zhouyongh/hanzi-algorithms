# 仓库在 GitHub 上的描述

发布时填进 GitHub 的那几个字段。**2026-10-25 实测上限**：
About 描述 **350 字符**（网上说的 160 是 GitHub Lists 的限制，不是仓库描述）；
Topics 最多 **20 个**、每个 ≤ **50 字符**、只能用小写字母数字与连字符。

## 参照：兄弟仓 hanzi-glyphs-svg 的写法

它的 About 描述是 **118 字符**，结构是「**一句中文（点明是什么 + 枚举涵盖范围）
＋ 一句英文（同样的结构）**」：

> 汉字字形 SVG 库：甲骨文、金文、篆书、隶书，以及楷书、行书、草书、宋体、黑体。
> Chinese glyph SVGs: oracle bone, bronze, seal, clerical, and modern scripts.

两点值得照抄：

- **中英文并列在一行里**，不是「中文长段 + 英文长段」；
- **不放数字、不放承诺**（它也没写「多少个字」）。

另外注意：它**没设 Topics**、**没填 Website**。Topics 确实对搜索有好处，
但既然兄弟仓这样，本仓也不强求——下面给了一份可选的。

## 一、About 描述（350 字符上限，只能填一个）

### 推荐：紧凑版（169 字符，与兄弟仓密度对齐）

```
汉字结构计算库：部首定位、构形分解、笔画切分、字形演变、隶变变换、竖排版式、描红评分。 Chinese character algorithms: radicals, IDS, strokes, glyph evolution, clerical scripts, vertical typesetting, trace scoring.
```

### 备选一：中等（238 字符，功能点写得更全）

```
汉字结构计算库：部首定位、IDS 构形分解、笔画切分、甲骨到隶书的字形演变、隶变变换、竖排与古籍版式、描红评分。 Chinese character algorithms: radical location, IDS decomposition, stroke segmentation, glyph evolution across scripts, clerical transformation, vertical typesetting, trace scoring.
```

### 备选二：带输入输出（207 字符，说清「吃什么吐什么」）

```
汉字结构计算库：输入字形 SVG，算出部首、笔画、构件、演变与版面。 Chinese character algorithms on glyph outlines: radical location, strokes, IDS decomposition, glyph evolution, clerical transformation, vertical typesetting, trace scoring.
```

## 三、其它字段（照兄弟仓的样子）

| 侧栏 About | 留空——README 已经承担了 |
| Issues | 兄弟仓开着，本仓也开 |
| Discussions | 兄弟仓没开，本仓也不强求 |

## 四、两条不要

- **描述里不放数字。** 「构形准确率 65.2%」这种放进 README 的实测表——
  GitHub 的 About 是长期字段，数字会过时，而它几乎不能改。
- **描述里不写承诺。** 不写「准确率超过某某」——那是 README 里带口径与样本量的地方。
